# 가상 메모리

## 물리 주소와 논리 주소

`물리 주소` : 하드웨어 상의 실제  주소<br>
`논리 주소` : 프로세스마다 부여되는 0부터 시작되는 주소

> 같은 물리 주소는 존재할 수 없지만 같은 논리 주소는 존재할 수 있다.

실제 정보가 담긴 물리 주소를 찾기 위해 `MMU(Memory Management Unit)`가 필요하다.

## 스와핑과 연속 메모리 할당

`스와핑` : 사용되지 않는 프로세스를 임시로 스왑 영역( 보조기억장치 - ssd 등 )으로 쫒아내 메모리상의 빈 공간을 만들어 다른 프로세스를 적재하는 방식<br>
스왑 아웃 (내쫒기)<-> 스왑 인 (들이기)

#### 연속 메모리 할당, 외부 단편화

연속 메모리 할당을 통해 프로세스별로 메모리할당을 묶을 경우 `외부 단편화`가 발생<br>
A/B/C 가 50/30/100 의 연속된 메모리를 점유하고 있다가 B 프로세스가 종료되면 A, C 사이에 남은 공간이 재할당되기 어려울 수도 있음<br>
이렇게 단편화된 메모리로 인해 사용 가능한 총 메모리 양은 넉넉해도 실제 프로세스를 적재할 공간이 부족하게됨

## 페이징

`가상 메모리` : 실행할 프로그램의 일부만 메모리에 적재하여 큰 프로세스를 실행할 수 있도록 하는 기법

`페이징` : 논리주소를 일정 단위 `페이지`로 나누고 물리주소 공간을 일정단위 `프레임`으로 나눠 페이지를 프레임에 할당하는 메모리 관리 기법<br>
세그먼테이션 -> 가변길이의 세그먼트로 나누어 분할하는 방식, 외부 단편화 발생할 수 있음

페이징 해도 프레임 단위보다 작은 빈공간이 생겨 `내부 단편화`가 발생할 수 있다.<br>
페이지 단위로 스와핑을 통해 페이지 아웃, 페이지 인 하여 가상 메모리 방식을 사용할 수 있음

#### 페이지 테이블
물리 메모리 내에 페이지가 불연속 적으로 있게되면 CPU는 다음 실행할 페이지를 찾기 어려워짐<br>
`페이지 테이블` : 페이지 번호와 실제 적재된 프레임 번호를 대응시킨 테이블을 통해 CPU가 프레임을 찾아간다.<br>
프로세스마다 페이지 테이블이 있다. (실제 더 많은 정보가 페이지 테이블에 담김)
