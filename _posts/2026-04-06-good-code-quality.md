## 코드 품질

고품질 코드는 신뢰할 수 있고, 유지보수가 쉬우며, 버그가 없어야 한다.

코드의 목표는 작동하고 멈추지 않으며, 환경·사용자·가정의 변화와 새 기능 요구에 적응하는 것이다. 이미 해결된 하위 문제를 다시 구현하지 않는 것도 중요하다.

## 품질의 핵심 요소

1. **읽기 쉬움** — 코드가 하는 일, 수행 방식, 필요한 것, 실행 결과를 파악할 수 있어야 한다.
2. **예측 가능성** — 기대를 벗어나는 동작은 버그를 유발할 수 있다.
3. **오용하기 어려움** — 잘못된 사용을 구조적으로 제한한다.
4. **모듈화** — 구성 요소를 쉽게 교체하고, 인터페이스로 상호작용 지점을 최소화한다.
5. **재사용·일반화** — 여러 상황에서 재사용하거나 유사한 다른 문제에 적용할 수 있다.
6. **테스트 용이성** — 단위·통합·종단간 테스트로 동작을 확인할 수 있어야 한다.

## 추상화 계층과 API

문제를 하위 계층으로 나누어 추상화하면 각 계층에서 적은 수의 개념만 다룰 수 있어 복잡도가 줄어든다. 추상화는 가독성, 모듈화, 재사용성, 테스트 용이성에 도움을 준다.

API는 호출하는 쪽에 공개할 개념만 정의한다. 함수는 작고 명확한 작업을 수행하고, 클래스는 응집력 있게 한 가지 관심사에 집중하며, 인터페이스는 구현 세부사항을 숨긴다. 인터페이스는 여러 구현과 테스트에 유리하지만 코드 복잡도와 작업량을 늘릴 수 있다.

원문에는 `null`의 부재 의미와 Null 안정성 예시도 포함되어 있다.
