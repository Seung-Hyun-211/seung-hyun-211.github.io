# CPU 스케줄링

### 우선순위
- `CPU 스케줄링` : CPU 자원을 관리
- `CPU 스케줄러` : CPU 자원을 관리하는 운영체제의 부분
- 우선순위 : 운영체제가 분리한 프로세스별 우선순위, PCB에 명시됨, 빨리 많은 자원을 할당함
- CPU 활용률 : 작업을 처리하는 시간의 비율, 입출력이 많은 작업일수록 높은 우선순위
- CPU 버스트 : 프로세스가 CPU를 이용한작업
- IO 버스트 : 프로세스가 IO 이용한 작업

IO 집중 프로세스를 빨리 실행시켜 끊임없이 IO장치를 작동하고, CPU집중 프로세스에 집중적으로 CPU를 할당

- CPU 집중 프로세스 : CPU작업이 많은 프로세스, 대기상태가 짧다
- IO 집중 프로세스 : IO작업이 많은 프로세스, 대기상태가 길다

> CPU 이용률 향상 : I/O 중심 프로세스는 CPU를 짧게 사용한 후 입출력을 요청하고 대기 상태로 전환, 이때 다른 프로세스를 실행<br>
> 자원 활용의 효율성 : CPU와 I/O 장치가 동시에 작업할 수 있도록 하여 전체적인 시스템 효율을 높일 수 있습니다.

### 스케줄링큐

각 컴퓨터를 사용할 프로세스의 PCB를 큐에 줄세운다.(반드시 선입선출은 아님)

대표 큐
- 준비큐 : CPU 자원사용 대기 -> Dispatch를 통해 실행상태로, 실행상태에서 타이머 인터럽트로 다시 준비큐로
- 대기큐 : IO 자원사용 대기 -> 입출력 인터럽트를 통해 준비큐로

---

실행중인 프로세스가 스케줄링 상태로 변경되는 조건
- 입출력 대기 상태로 전환
- 타이머 인터럽트 발생

---

선점형 스케줄링 : 운영체제가 강제로 CPU자원을 빼앗아 스케줄링
비선점형 스케줄링 : 프로세스가 스스로 종료, 대기상태로 전환되기 전까지 끼어들 수 없는 스케줄링

## 리눅스 CPU 스케줄링

- CFS(completely fair scheduler) : 공평한 시간배분을 지향하는 스케줄링
  <br>프로세스마다 가상 실행 시간 (vruntime) 정보를 유지하여 가장 작은 프로세스부터 스케줄링한다. 실제 시간이 아닌 가중치를 계산해서 사용
- EEVDF(earliest eligible virtual deadline first) : 가장 빠른 마감 우선 스케줄링 알고리즘
  <br>cpu 시간의 공정성을 유지하며 자원을 할당받을 자격이 있는 작업중 가장빠른 마감이 가능한 작업을 선택
