# 프로세스와 스레드

## 프로세스

- 포그라운드 프로세스 : 사용자가 보는 곳에서 진행되는 프로세스
- 백그라운드 프로세스 : 사용자가 보지 않는 곳에서 진행되는 프로세스
- 데몬( = 윈도우에서는 "서비스") : 사용자와 상관 없이 진행되는 프로세스

## 프로세스의 시작
 커널 영역 메모리에 -> `PCB`<br>
 사용자메모리에 -> `code` `data` `heap` `stack`

## 사용자 영역
  - Code : 컴파일된 프로그램의 코드가 적재되는 영역
  - Data : 전역, 정적 변수가 저장되는 영역
  - Heap : 사용자(개발자)가 직접 할당, 해제 하는 영역, 메모리 누수에 주의, FIFO
  - Stack : 매개변수, 지역변수, 함수의 복귀주소 등이 저장되는 영역, FILO


## 커널 영역
  - PCB(process control block) :  프로세스에 대한 정보저장을 위해 사용하는 자료구조, 운영체제가 관리
    - 식별정보
    - 상태정보
    - 제어정보
  - 프로세스 테이블 : 프로세스 실행시 추가되고 종료시 제거되는 PCB들이 담긴 테이블

### 컨텍스트 스위칭
타임아웃 인터럽트 발생시 현재 프로세스의 문맥 정보를 PCB저장(백업)하고 다음 프로세스의 문맥 정보를 불러오는 과정<br>
스위칭이 자주 발생하면 캐시미스와 오버헤드가 증가하여 불이익이 발생한다.

`타입아웃 인터럽트` : CPU 사용시간 제한이후 발생하는 인터럽트

## 프로세스상태

- 생성 : 프로세스 생성중인 상태, PCB 메모리 할당
- 준비 : CPU 자원 할당을 기다리는 상태, `Dispatch`를 통해 실행상태로 변환
- 실행 : CPU 자원을 받아 실행중인 상태, `Timer Interrupt`를 통해 대기상태로 변환
- 대기 : 실행상태에서 바로 진행이 불가능한 경우(ex.입출력) 기다리기 위해 대기상태로 변환됨, 준비 단계로 돌아감
- 종료 : 프로세스가 종료된 상태, PCB와 메모리를 정리함

blocking I/O : 실행상태에서 시스템 콜 이후 대기로 전환되는 입출력, 리턴을 기다림<br>
non-blocking I/O : 시스템 콜 이후 바로 리턴을 받아 실행을 이어가는 입출력


## 멀티프로세스, 멀티스레드
- 멀티프로세스
  - 동시에 여러 프로세스가 실행됨
  - 자원 공유 X
  - 독립적으로 실행 (PID다름)
  - 독립적으로 자원 할당, 남남처럼 실행
- 멀티스레드
  - 한 프로세스 내에서 실행되는 여러 스레드
  - 프로세스의 자원을 공유
  - 쉽게 협력하고 통신가능
  - 한 스레드에 문제발생시 프로세스에 영향

## 프로세스간 통신

Inter-Process Communication

- 공유 메모리 : 특정 메모리 영역을 공유하여 데이터를 주고받음
  - 각 프로세스가 자신의 메모리 영역을 읽고 쓰는 것처럼 통신
  - 커널 개입 X
  - 레이스컨디션, 동기화 문제
- 메시지 전달 : 커널을 통한 메시지 송수신
  - 공유 메모리보다 느림
  - 파이프 : 단방향 통신도구, 읽기용 쓰기용 파이프로 양방향 통신
    - unnamed pipe 단방향, 부모 자식 프로세스간
    - named pipe 양방향, 임의의 프로세스간
  - 시그널 : 프로세스에게 이벤트 발생을 알림, 시그널 핸들러를 통해 이벤트를 처리함
  - 소켓, 원격 프로시저 호출(RPC)
