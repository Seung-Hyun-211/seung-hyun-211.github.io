코드를 재사용하거나 범용적으로 만들면 중복을 줄일 수 있지만, 원래 코드가 가진 전제와 새 사용처의 요구가 다르면 오히려 오류가 숨어들 수 있다.

## 전제를 드러내기

전제는 구현을 단순하고 효율적으로 만들 수 있지만, 암묵적이면 다른 상황에서 재사용될 때 취약점이 된다. 불필요한 가정을 줄이고 꼭 필요한 조건은 API 계약으로 분명히 하며, 위반 시 조기에 실패하도록 한다.

## 숨은 공유 상태 조심하기

전역 상태나 정적 변수는 호출 주체와 무관하게 여러 문맥에서 공유된다. 코드가 “항상 인스턴스 하나뿐”이라고 가정하면 테스트·동시 실행·여러 사용자 상황에서 문제가 될 수 있다. 공유해야 할 상태라면 의존성으로 전달해 소유권과 수명주기를 명시한다.

## 기본값과 함수 매개변수

상위 계층에서는 구체적인 기본 동작을 정하기 쉬운 반면, 여러 상황에서 재사용되는 하위 계층의 기본값은 특정 사용처에 편향될 수 있다. 기본값이 적절하지 않다면 호출자가 선택하도록 한다.

매개변수가 지나치게 많아지면 호출과 재사용이 어려워질 수 있다. 관련 설정을 하나의 타입으로 묶거나 책임을 나누는 방안을 살펴본다. 특정 자료형에 묶이지 않아도 되는 로직은 제네릭·템플릿으로 일반화할 수 있지만, 실제 요구 없이 복잡성만 늘리지 않는다.
