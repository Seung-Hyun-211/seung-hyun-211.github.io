## 서술형 명칭

변수·함수·클래스의 이름만으로 역할을 이해할 수 있으면 주석보다 코드에 집중하기 쉽다.

```cpp
team.ContainsPlayer(name);
```

## 주석은 필요한 정보에 집중

주석은 코드가 무엇을 하는지, 왜 그렇게 하는지, 사용 지침이나 추가 정보를 설명할 수 있다. 가능하다면 주석을 늘리기보다 의미가 드러나는 코드를 작성한다.

```cpp
// 성과 이름이 들어 있는 배열을 합침
return data[1] + "." + data[0];

// 역할을 이름으로 표현
return FirstName(data) + "." + LastName(data);
```

코드가 왜 필요한지 설명하는 주석은 버전 변경이나 요구사항 같은 맥락을 전달할 수 있다. 다만 모든 문단에 요약을 반복하면 읽을 것이 많아져 방해가 된다. 장이나 표지 수준의 상위 정보는 유용할 수 있다.

## 읽기 쉬운 구조

- 코드 줄 수를 무조건 줄이지 않는다. 이해하기 쉽고 오해하기 어려운 표현이 더 중요하다.
- 일관적인 코딩 스타일을 유지한다.
- 깊은 중첩은 재배치하거나 기능을 별도 함수로 나눠 줄인다.
- 함수 이름과 매개변수 이름으로 호출 결과를 예측할 수 있게 한다.
- 설명이 되지 않는 매직값을 피한다.
- 간단한 로직에는 익명 함수를 쓸 수 있지만 가독성을 확인한다.
